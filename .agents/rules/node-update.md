# 小记维护规则

适用于新增或修改小记，不用于修改修炼笔记页面的功能。

## 更新顺序

1. 先修改 `docs/note.md`。它是完整小记的唯一来源，最新日期放在最上面，日期标题沿用 `## **时间** : YYYY-MM-DD`。同日内容合并到现有条目，不重复建日期标题；保留往期内容。
2. 再同步 `README.md` 的「更新日记」。只保留 `docs/note.md` 的最新一篇，日期、正文和链接保持一致。复制时将相对图片或文件链接改为以仓库根目录为基准的路径。
3. 在 README 最新小记末尾保留 `[往期小记](https://gitbyeos.github.io/open-part-skills/#notes)`，指向工具箱的「修炼笔记」，不要重复添加入口。

## 验收与发布

- 对照两个文件，确认最新小记一致、「往期小记」链接存在，旧条目没有丢失。
- 在仓库根目录运行 `./tools/notes/build.sh`，检查生成的 `tools/notes/dist/index.html` 能展示最新条目。纯文案更新不改测试，也不提交 `dist/`；GitHub Pages 发布时会重新构建。
- 发布后确认 Pages 工作流成功，并打开「往期小记」验证最新条目已上线。
