# 七维描述

输入为自由描述。直接出稿，不先追问。一次只处理一件事；多件事拆成多份，每份独立成稿。推测只依据这段输入里的场景，不搬示例原句。

先输出下面八行，空一行，再写收句。收句为两句或三句白话。不加导语、不加解释、不加额外标题。八行标签、顺序和“于时间…在…”句式保持不变。

## 模板

```text
【事件主体】{事件发生在谁身上}
【时间/地点】于时间 {时间} 在 {地点}
【事件细节】{发生了什么}
【成因/动机】{反馈方给出的原因或动机}
【期望/决策】{希望得到的结果，或已经做出的决定}
【谁来处理】{交给谁}
【你的诉求】{希望对方做什么}
【关键信息缺失】
```

【成因/动机】、【期望/决策】：可从用户描述自行推测，用委婉说法写上，句末加（推测）。

【时间/地点】：包括地理位置、游戏虚拟场景、群聊、文档等。

【谁来处理】写交给谁，称呼照原话。推不出写“未知处理人”。

【你的诉求】写希望对方做什么，请求照原话，不改写成调查步骤。推不出写“未知诉求”。

## 关键信息缺失

八行均须出现。无缺项时，末行只有“【关键信息缺失】”。有缺项时，缺失项写在段名同一行，用顿号连接，顺序固定：

```text
【关键信息缺失】事件主体、时间/地点、事件细节、成因/动机、期望/决策、谁来处理、你的诉求
```

写成“未知……”或标了（推测）的段仍算缺项。只有照实写明、且达到下限的段，才不列入。

| 段 | 下限 | 推不出时 |
|---|---|---|
| 事件主体 | 写得出事件发生在谁身上 | 未知主体 |
| 时间/地点 | 时间和地点都写得出 | 未知时间、未知场景 |
| 事件细节 | 写得出发生了什么 | 未知细节 |
| 成因/动机 | 写得出原因或动机 | 未知成因 |
| 期望/决策 | 写得出期望结果或已做决定 | 未知期望 |
| 谁来处理 | 写得出交给谁 | 未知处理人 |
| 你的诉求 | 写得出希望对方做什么 | 未知诉求 |

时间或场景有一侧推不出，缺失行仍列“时间/地点”。

## 收句

八行之后空一行，用委婉语气写两句或三句白话，不带【】，不出现段名，不出现“未知”和“推测”。

- 第一句串起照实写明的主体、时间、地点、细节
- 第二句串起照实或推测的成因、主体诉求；推测去掉标记
- 第三句只写谁来处理、你的诉求
- 以“未知”开头的空位不写入收句
- 谁来处理和你的诉求都是未知时，不写第三句

## 示例

```text
输入：研发同学，帮看个反馈。玩家 10086 在 11-02 01:15 的 boss 挑战里，掉落无法拾取。
```

```text
【事件主体】玩家 10086
【时间/地点】于时间 11-02 01:15 在 boss 挑战中
【事件细节】掉落物品无法拾取
【成因/动机】玩家认为是 BUG 造成的（推测）
【期望/决策】玩家希望得到补偿（推测）
【谁来处理】研发同学
【你的诉求】帮看个反馈
【关键信息缺失】成因/动机、期望/决策

玩家 10086 于 11-02 01:15 在 boss 挑战中，掉落物品无法拾取。玩家认为是 BUG 造成的，希望得到补偿。麻烦研发同学看这个反馈。
```
